The Bridge: How To one contract, six carriers

Two programs that talk to each other cannot hand each other an object: a C host has no script dictionary, the engine cannot see a C struct, a Python host has no COM pointer, and a COM client has no UTF-8 buffer of its own. What crosses every one of those boundaries is UTF-8 text. The Bridge is therefore one request document in and one response document out, in both directions, and the object graph stays where it lives.

This page covers the whole contract and the six carriers that were driven through it end to end: C, C#, Python, PowerShell, Java and COM. Each section carries a complete sample and the one or two details that decide whether it works.

What it is

Two doors, one dispatch, so a host and a script cannot disagree about what a request means:

DoorWhat it does
Bridge.Serve(handler)The script registers the function that answers the host. The host drives it.
Bridge.Handle(request)The host to script door, as text in and text out. This is what every carrier calls underneath, and it is also what a test drives, so a stub host is a script.
Bridge.Call(request)The script to host door. Answers the host's response document already parsed, so a script reads answer["r"]["n"].

The carrier only decides how the document travels. A C host installs a callback with slc_set_bridge and drives the script with slc_invoke; a COM client reaches the script with one Invoke member; a .NET host that owns the interpreter sets one field. Swapping the carrier changes no script, which is the reason the contract exists as a contract rather than as six protocols that resemble each other.

The envelope

A request is a JSON object with four members. Two are required.

MemberTypeMeaning
vwhole numberRequired. The contract version. This build speaks 1, and another value is refused by name rather than mis-read.
idany JSON valueOptional. The caller's correlation id. It is echoed verbatim, including an explicit null, and a request with no id member gets no id in the answer. The dispatcher writes it, so a handler cannot forget it or substitute somebody else's. It is how a host matches an answer to its request in a log: no carrier allows two requests outstanding at once, so pipelining would need a batch, which this version does not define.
mtextRequired. The verb, a dotted name such as invoice.post. It is the only thing a handler dispatches on.
pJSON objectOptional. The parameters. An explicit null is the same as leaving it out, which is stated rather than left to a handler to guess. Anything large is paged inside it, because a contract that allows one huge value invites a payload no reader can bound.

A response is also one object, and exactly one of r or e is present:

MemberTypeMeaning
vnumberThe contract version the answer was built for. Always 1, written by the dispatcher.
idanyThe request's id, echoed by construction, including null. No id member in the request, no id in the answer.
okbooleanRequired. The verdict of the request.
rany JSON valueThe result, when ok is true.
eobjectThe error, when ok is false.

The error object's four base members are always present. at and frames appear when the engine caught the failure, and retryAfter and details when the handler has something more to say:

MemberMeaning
codeA short, non-empty, stable name a host branches on: BadRequest, UnsupportedVersion, NoSuchVerb (the handler's own), or one of the engine's error codes.
messageOne non-empty sentence, in the engine's or the handler's voice, naming what to fix. Never a CLR resource key.
retryA boolean. true means the same request may succeed later (a busy resource), which is what a host needs to decide between an error dialog and a backoff. retryAfter says how long to wait.
origin"engine" when the dispatcher or the engine built the failure (a refusal, or a handler that threw), "handler" when the handler answered it with Bridge.Fail or Bridge.FromError. The dispatcher forces it, so a handler cannot claim the engine's voice.
retryAfterA whole number of milliseconds. Meaningful when retry is true, and what a host uses as its backoff.
detailsA JSON object the APPLICATION owns, such as { "field": "total" }. The engine never interprets it; it is where a validation failure names the parameter that was wrong.
at{ "file": "...", "line": 12, "col": 5 }, when the ENGINE caught the failure: the script that registered the handler and the position inside it.
framesThe engine's call frames, innermost first, as "Post [L10:C9]". Present when there are any.

The seven rules

  1. One verb shape. Both directions use the same document, so a log or a fixture is readable without knowing which side produced it.
  2. No re-entry on the same session. A session serves one host request at a time. A handler MAY call the host with Bridge.Call; what is refused is Bridge.Handle on its own session, a verb issued from inside a host callback (a run posted there would wait on itself), and a host that answers Bridge.Call by calling back into the same session. Each of those is a loop, which is why the rule is about re-entry rather than about depth.
  3. Nothing throws across. A handler that throws becomes ok:false with the engine's code, message, position and frames. A host that throws, or that answers a negative length, is a refusal the script can catch at the Bridge.Call that reached it.
  4. m is additive only. A verb may be added at any time. Removing one, or changing what one means, is a contract version bump, which is what v is for. A reader tolerates members it does not know, so a newer side does not break an older one.
  5. p is an object, absent, or explicitly null. A null means the same as absent. Arrays and scalars travel inside it.
  6. id is echoed by construction. The dispatcher rewrites it from the request, null included, so a handler cannot forget it. It is how a host matches an answer to its request in a log; no carrier allows two requests outstanding, so pipelining would need a batch, which version 1 does not define.
  7. A response is validated. The whole shape, not only ok: text that is not an object, a missing or non-boolean ok, an ok:true answer carrying e, an e that is not an object, or an error whose code or message is missing or not a non-empty string is HandlerReturnedNonEnvelope, never forwarded to a host that would have to guess. An ok:false answer carrying r has the r dropped, because exactly one of the two shapes is present.

The refusals

Every one of these arrives as a normal answer, so a host parses one shape and reads e.code.

CodeWhen
BadRequestThe request is not a JSON object at all.
UnsupportedVersionv is missing, is not a whole number, or names another contract version. The message says which one it read.
MissingMethodm is missing or empty.
BadParamsp is present and is not a JSON object. An explicit null is treated as absent.
NoHandlerThe script has not called Bridge.Serve, or a later run unregistered it.
HandlerReturnedNothingThe handler answered null, or something that is not text. A verb must end with Bridge.Ok or Bridge.Fail.
HandlerReturnedNonEnvelopeThe handler's text is not a JSON object, has no boolean ok, carries e beside ok:true, has an e that is not an object, or has an error whose code or message is missing or not a non-empty string.
FailedA handler reported a failure without a reason, and the dispatcher filled one in.
the engine's own codeA handler that threw answers its own code (Unspecified for a plain failure, DivisionByZero, UndefinedVariable, Cancelled, and so on) with its message, at and frames.
A verb the host does not know is the handler's decision, not the dispatcher's. The dispatcher only checks the envelope. A handler that receives an unknown Verb and answers req.Fail("NoSuchVerb", ...) is what makes the refusal app-specific; a handler that ignores the verb and answers req.Ok(...) is equally legal, and that is the contract being silent about verbs rather than vague.

Two kinds of failure

A contract failure is an answer. An unknown verb, another version, a handler that threw: all of them travel INSIDE the document as ok:false, so the transport succeeded and the code is a value a host branches on.

A transport failure is not an answer. No such session, a session already running, a freed handle, a callback that could not be called: there is no document to parse, so the carrier says so in ITS OWN vocabulary and the reason goes to the carrier's error channel.

CarrierContract failureTransport failure
C, C#, Python, PowerShell, JavaThe document's own ok:false, a non-negative lengthslc_invoke answers a NEGATIVE status; the sentence is in slc_last_error
the host half (C, C#, Python, PowerShell, Java)the host's own ok:false documentthe callback answers a NEGATIVE length; the script catches the refusal at Bridge.Call
COMthe document's own ok:false, and the HRESULT stays 0the sentence in LastError (a freed object, a session already running), because a member has no status to answer

Putting a sentence in a buffer the host parses as JSON is how a binding ends up reporting a parse error instead of the real problem. That is why a transport failure is never a document.

A handler that serves two verbs

Bridge.Serve(fun (req) {
    var verb = req.Verb;                                    // the typed request: Verb, Id, Version, Parameters, Document
    if (verb == "invoice.post") {
        if (req.Parameters["total"] < 0) { return req.Fail("BadTotal", "a total cannot be negative"); }
        return req.Ok({ posted: true, invoice: 4171 });      // the id is the request's, echoed for you
    }
    if (verb == "invoice.get") {
        return req.Ok({ invoice: 4171, total: 120.50 });
    }
    return req.Fail("NoSuchVerb", "this script serves invoice.post and invoice.get, not " + verb);
});

Answering a failure the script handled

Bridge.Serve(fun (req) {
    try {
        return req.Ok({ rows: Database.Rows(req.Parameters) });

});

A stub host is just a script. Bridge.Handle answers the same document every carrier receives, so the contract can be tested with no host technology at all. That is what assets/language/repl/interop/bridge_contract_test.slc does: it decides the version, the verb, the parameters object (including an explicit null), a handler being served, a re-entrant call and a handler calling the host while serving, a handler's own failure, a non-envelope answer, the answer's whole shape (exactly one of r or e, and the error's code, message, origin, retryAfter and details), a response that names somebody else's id and version, and the id echoed four ways (string, numeric, absent, null). It runs on both engines.

The published library is x64 (PE32+). Every carrier needs a 64-bit host process: a 32-bit Python, PowerShell, JVM or Office gets "the specified module could not be found" or "class not registered", which reads like a missing install rather than a bitness mismatch.

C

A C host links nothing from the engine: it resolves the exports by name at run time, which is what a host without an import library does. The generated header bindings/ScriptLangCore.h declares all of them; the sample below spells only the six it uses and is shipped as bindings/bridge_host.c, so it can be built and run against an installed engine instead of retyped.

/* bridge_host.c: the Bridge contract from a C host, both directions, with no import library and NO C RUNTIME.
 *
 * THIS IS THE SHIPPED C CARRIER, beside `BridgeTest.py` (the Python one) in `bindings\`, the folder the installer copies
 * to `{app}\bindings`: a host builds and runs this proof against an installed engine instead of retyping it, which is
 * what the Bridge page's own block is (`docs\bridge\howto.html`, the C section), so the two cannot drift.
 *
 * BUILD, with an x86_64 MinGW-w64 GCC (see the three rules below), from this folder:
 *   set PATH=C:\msys64\mingw64\bin;%PATH%
 *   gcc -std=c11 -Oz -fno-stack-protector -mno-stack-arg-probe -falign-functions=1 -falign-jumps=1 ^
 *       -falign-loops=1 -falign-labels=1 -fno-plt -s -Wall -Wextra -Werror -mconsole -ffunction-sections ^
 *       -fno-asynchronous-unwind-tables -fno-unwind-tables -fdata-sections -fno-ident -fno-builtin ^
 *       -Wl,--gc-sections -Wl,--build-id=none -Wl,--no-insert-timestamp -nostartfiles -nostdlib ^
 *       -e wmainCRTStartup -o bridge_host.exe bridge_host.c -lkernel32
 *
 * RUN it with the engine DLL's path:
 *   bridge_host.exe "C:\Program Files\ScriptLangCore\bin\ScriptLangCore.dll"
 *
 * THREE RULES THIS FILE OBEYS, because -nostartfiles -nostdlib changes what "a C program" is:
 *   1. IT MUST BE AN x64 COMPILER, because the engine image is x64: a 32-bit host answers LoadLibrary = 193
 *      (ERROR_BAD_EXE_FORMAT) before a single export is looked up. `gcc -dumpmachine` must say x86_64-w64-mingw32.
 *   2. -fno-builtin, because GCC recognises the byte loops below as strlen/memcpy and would emit CALLS to them, which
 *      nothing provides here (without it the link fails on an undefined `strlen`).
 *   3. -lkernel32, because -nostdlib names every library explicitly: the entry point, the output and every Win32 call
 *      come from there, and WITHOUT it the link stops on `LoadLibraryW`.
 *
 * WHAT IS GONE, and why: no stdio, no string.h, no main(). This program writes with WriteFile on the inherited handle
 * and takes its one argument off GetCommandLineW, so the image is a few kilobytes instead of 250 KB of CRT.
 */

 * typedefs are what the compiler checks the host's call sites against instead of an import library. */
typedef int64_t (*create_fn)(const char *options);
typedef int     (*free_fn)(int64_t handle);
typedef int     (*last_error_fn)(int64_t handle, char *buffer, int capacity);
typedef int     (*run_text_fn)(int64_t handle, const char *source, const char *name);
typedef int     (*set_bridge_fn)(int64_t handle, void *callback, void *user);
typedef int     (*invoke_fn)(int64_t handle, const char *request, char *buffer, int capacity);

/* A FARPROC is a function pointer of UNKNOWN signature, so casting it to one of the types above is a cast between
 * incompatible function types: -Wcast-function-type refuses it, correctly, because calling through such a cast is
 * undefined. Storing its REPRESENTATION into a correctly typed pointer is the idiom that IS well defined, and these
 * asserts are what make the copy exact rather than hopeful (every pointer is one machine word, in both image kinds). */
_Static_assert(sizeof(FARPROC) == sizeof(void *), "a FARPROC is one machine word");
_Static_assert(sizeof(create_fn) == sizeof(void *), "an export pointer is one machine word");
_Static_assert(sizeof(free_fn) == sizeof(void *), "an export pointer is one machine word");
_Static_assert(sizeof(last_error_fn) == sizeof(void *), "an export pointer is one machine word");
_Static_assert(sizeof(run_text_fn) == sizeof(void *), "an export pointer is one machine word");

_Static_assert(sizeof(invoke_fn) == sizeof(void *), "an export pointer is one machine word");

static HANDLE g_out;                       /* stdout, taken once: with no CRT there is no stdout of its own */
static int64_t g_session;
static invoke_fn g_invoke;
static last_error_fn g_last_error;
static char g_answer[8192];                /* the host's answer buffer, static so no stack probe is needed */
static char g_narrow[4096];

/* ---- the two primitives a CRT would have given: a length and a byte copy -------------------------------------- */
static unsigned long long text_length(const char *text)
{
    unsigned long long n = 0;
    if (text != NULL) { while (text[n] != '\0') n++; }
    return n;
}

static void copy_bytes(void *destination, const void *source, unsigned long long count)
{
    unsigned char *to = (unsigned char *)destination;
    const unsigned char *from = (const unsigned char *)source;
    while (count > 0) { *to++ = *from++; count--; }
}

/* ---- output: WriteFile on the inherited handle, so a redirected stream keeps working --------------------------- */
static void say(const char *text)
{
    DWORD written = 0;
    unsigned long long n = text_length(text);
    if (g_out == NULL || g_out == INVALID_HANDLE_VALUE || n == 0) return;
    WriteFile(g_out, text, (DWORD)n, &written, NULL);
}

static void say_uint(unsigned long value)
{
    char digits[21];
    int at = 20;
    if (value == 0) { say("0"); return; }
    digits[at] = '\0';
    while (value > 0) { digits[--at] = (char)('0' + (int)(value % 10)); value /= 10; }
    say(digits + at);
}

static void say_wide(const wchar_t *wide)
{
    int n = WideCharToMultiByte(CP_UTF8, 0, wide, -1, g_narrow, (int)sizeof(g_narrow), NULL, NULL);
    if (n > 0) say(g_narrow);
}

static void end_line(void)
{
    say("\r\n");
}

/* ---- loading an export by name: a representation copy, never a cast between function types -------------------- */
static int load_export(HMODULE dll, const char *name, void *slot, unsigned long long size)
{
    FARPROC raw = GetProcAddress(dll, name);
    if (raw == NULL) return 0;
    copy_bytes(slot, &raw, size);
    return 1;
}

static const char *last_error_text(void)
{
    static char buffer[1024];
    if (g_last_error == NULL) return "";
    return g_last_error(g_session, buffer, (int)sizeof(buffer)) > 0 ? buffer : "";
}

/* THE HOST HALF: one request document in, one response document out. Answer the length the document NEEDS, write at
 * most capacity - 1 bytes plus a terminator, and a NEGATIVE answer means this host refuses the request. */
static int32_t host_bridge(int64_t handle, void *user, const char *request, char *buffer, int32_t capacity)
{
    static const char response[] = "{\"v\":1,\"ok\":true,\"r\":{\"name\":\"Ada\"}}";
    int32_t length = (int32_t)text_length(response);
    (void)handle;
    (void)user;
    say("  the script asked: ");
    if (request != NULL) say(request);
    end_line();
    if (buffer != NULL && capacity > 0) {
        int32_t copy = length < capacity - 1 ? length : capacity - 1;
        copy_bytes(buffer, response, (unsigned long long)copy);
        buffer[copy] = '\0';
    }
    return length;
}

/* One slc_invoke, the way a host does it: capacity 0 asks for the length, then a buffer of that size. */
static int ask(const char *request)
{
    int needed = g_invoke(g_session, request, NULL, 0);
    if (needed < 0) {
        say("  transport failure: ");
        say(last_error_text());
        end_line();
        return -1;
    }
    if (needed + 1 > (int)sizeof(g_answer)) {
        say("  the answer needs ");
        say_uint((unsigned long)needed);
        say(" bytes");
        end_line();
        return -1;
    }
    if (g_invoke(g_session, request, g_answer, needed + 1) < 0) {
        say("  transport failure: ");
        say(last_error_text());
        end_line();
        return -1;
    }
    return needed;
}

/* ---- the command line: with no CRT nobody hands us argv, so one token is read from GetCommandLineW ------------- */
/* Takes the token at `at` into `into` (quoted tokens keep their spaces, and the quotes are dropped). A NULL `into`
 * skips the token, which is how the program's own path is stepped over. Returns where the next token starts. */
static const wchar_t *take_token(const wchar_t *at, wchar_t *into, unsigned long long capacity)
{
    unsigned long long n = 0;
    while (*at == L' ' || *at == L'\t') at++;
    if (*at == L'\0') return NULL;
    if (*at == L'"') {
        at++;
        while (*at != L'\0' && *at != L'"') {
            if (into != NULL && n + 1 < capacity) into[n++] = *at;
            at++;
        }
        if (*at == L'"') at++;
    } else {
        while (*at != L'\0' && *at != L' ' && *at != L'\t') {
            if (into != NULL && n + 1 < capacity) into[n++] = *at;
            at++;
        }
    }
    if (into != NULL && capacity > 0) into[n < capacity ? n : capacity - 1] = L'\0';
    return at;
}

static unsigned run(void)
{
    static wchar_t dll_path[1024];
    create_fn p_create;
    free_fn p_free;
    run_text_fn p_run_text;
    set_bridge_fn p_set_bridge;
    HMODULE dll;
    int loaded;

    const wchar_t *after_exe;

    g_out = GetStdHandle(STD_OUTPUT_HANDLE);

    /* argv[0] is this program's own path; argv[1] is the engine's. A missing one is a usage refusal, exit 2. */
    after_exe = take_token(GetCommandLineW(), NULL, 0);
    if (after_exe == NULL || take_token(after_exe, dll_path, 1024) == NULL) {
        say("usage: bridge_host.exe <ScriptLangCore.dll>");
        end_line();
        return 2;
    }

    dll = LoadLibraryW(dll_path);
    if (dll == NULL) {
        say("LoadLibrary(");
        say_wide(dll_path);
        say(") = ");
        say_uint((unsigned long)GetLastError());
        end_line();
        return 2;
    }

    loaded  = load_export(dll, "slc_create", &p_create, sizeof p_create);
    loaded &= load_export(dll, "slc_free", &p_free, sizeof p_free);
    loaded &= load_export(dll, "slc_last_error", &g_last_error, sizeof g_last_error);
    loaded &= load_export(dll, "slc_run_text", &p_run_text, sizeof p_run_text);
    loaded &= load_export(dll, "slc_set_bridge", &p_set_bridge, sizeof p_set_bridge);
    loaded &= load_export(dll, "slc_invoke", &g_invoke, sizeof g_invoke);
    if (!loaded) {
        say("this engine has no bridge: ask for capability 0x200 (slc_capabilities)");
        end_line();
        return 2;
    }

    g_session = p_create("{\"thread\":\"own\"}");
    if (g_session <= 0) {
        say("slc_create: ");
        say(last_error_text());
        end_line();
        return 2;
    }

    /* The host half, installed once. NULL removes it. */
    if (p_set_bridge(g_session, (void *)host_bridge, NULL) != 0) {
        say("slc_set_bridge: ");
        say(last_error_text());
        end_line();
        return 1;
    }

    /* script -> host */
    p_run_text(g_session,
        "var who = Bridge.Call('{\"v\":1,\"id\":\"s1\",\"m\":\"customer.lookup\",\"p\":{\"id\":42}}');\n"
        "print(\"  customer: \" + who[\"r\"][\"name\"]);", NULL);

    /* host -> script: the script serves a verb, then the host invokes it */
    p_run_text(g_session,
        "Bridge.Serve(fun (req) {\n"
        "    var verb = \"\" + req[\"m\"];\n"
        "    if (verb == \"echo\") { return Bridge.Ok(req[\"id\"], { n: req[\"p\"][\"n\"] * 2 }); }\n"
        "    return Bridge.Fail(req[\"id\"], \"NoSuchVerb\", \"no \" + verb);\n"
        "});", NULL);

    if (ask("{\"v\":1,\"id\":\"h1\",\"m\":\"echo\",\"p\":{\"n\":21}}") >= 0) {
        say("  the script answered: ");

Details that decide whether it works

  • The two-pass length applies in BOTH directions. slc_invoke answers the length it needs for capacity 0, and your callback must answer the same way, because the engine probes before it allocates.
  • A negative answer from your callback is your refusal, and the script catches it at its Bridge.Call with the engine's own sentence. A negative answer from slc_invoke is a TRANSPORT failure: read slc_last_error, do not parse the buffer.
  • Ask for capability bit 0x200 (slc_capabilities) before relying on the two exports, and compare slc_abi_revision with 6. A build without the bit has no bridge and nothing else is missing.
  • The callback runs on the engine's thread (the session owns one), so it must not take a lock the calling thread holds, and it must not call back into the same session.
  • Your own process is x64. A 32-bit build of this sample cannot load the x64 DLL at all.

Details that decide whether it works

  • CallingConvention.Cdecl on the delegate, which is the ABI's convention. The default (Winapi, stdcall) corrupts the stack on x64 rather than failing a lookup.
  • Keep the delegate alive. A local that goes out of scope, or a lambda passed inline, can be collected while the engine still calls its pointer. A field, or a local that the last call can still see, is the fix.
  • The two-pass length, both directions. Marshal the answer with PtrToStringUTF8 rather than PtrToStringAuto, which reads UTF-16 on this platform.
  • A host that owns the interpreter directly (the engine's own embedding, and any host that drives a session in-process) sets HostBridge instead, a Func<string, string?>. It is the same field slc_set_bridge writes, so there is one implementation of the rule; an out-of-process or separate-assembly host uses the ABI.

Python

ctypes is in the standard library, so this carrier needs nothing installed. The declarations are also generated: bindings/scriptlangcore.py holds the signatures and the capability names. The sample below is shipped as bindings/BridgeTest.py, so it can be run rather than retyped: it checks both directions and every refusal in this section's list, and it ends with PYTHON BRIDGE OK, which is its exit code.

"""bridge_host.py: both directions over the C ABI, with the standard library only.
    python bridge_host.py C:\\Program Files\\ScriptLangCore\\bin\\ScriptLangCore.dll
"""
import ctypes
import sys

engine = ctypes.WinDLL(sys.argv[1])          # x64 CPython, because the library is x64

engine.slc_create.restype = ctypes.c_longlong
engine.slc_create.argtypes = [ctypes.c_char_p]
engine.slc_free.restype = ctypes.c_int
engine.slc_free.argtypes = [ctypes.c_longlong]
engine.slc_capabilities.restype = ctypes.c_int
engine.slc_capabilities.argtypes = []
engine.slc_last_error.restype = ctypes.c_int
engine.slc_last_error.argtypes = [ctypes.c_longlong, ctypes.c_char_p, ctypes.c_int]
engine.slc_set_output.restype = ctypes.c_int
engine.slc_set_output.argtypes = [ctypes.c_longlong, ctypes.c_void_p, ctypes.c_void_p]
engine.slc_run_text.restype = ctypes.c_int
engine.slc_run_text.argtypes = [ctypes.c_longlong, ctypes.c_char_p, ctypes.c_char_p]
engine.slc_set_bridge.restype = ctypes.c_int
engine.slc_set_bridge.argtypes = [ctypes.c_longlong, ctypes.c_void_p, ctypes.c_void_p]
engine.slc_invoke.restype = ctypes.c_int
engine.slc_invoke.argtypes = [ctypes.c_longlong, ctypes.c_char_p, ctypes.c_char_p, ctypes.c_int]

CAP_BRIDGE = 1 << 9
if (engine.slc_capabilities() & CAP_BRIDGE) == 0:
    raise SystemExit("this build has no bridge")

LINE_CB = ctypes.CFUNCTYPE(None, ctypes.c_longlong, ctypes.c_int, ctypes.c_char_p, ctypes.c_void_p)
# THE BUFFER IS c_void_p, NOT c_char_p. A c_char_p parameter arrives as an immutable Python bytes object, so a
# write into it is lost and this host would answer a length for a document it never wrote.
BRIDGE_CB = ctypes.CFUNCTYPE(ctypes.c_int, ctypes.c_longlong, ctypes.c_void_p,
                             ctypes.c_char_p, ctypes.c_void_p, ctypes.c_int)

lines = []
requests = []

def on_line(handle, channel, utf8, user):
    lines.append(str(channel) + "|" + (utf8 or b"").decode("utf-8"))

def on_request(handle, user, request, buffer, capacity):
    """The host half: the length the response needs, at most capacity - 1 bytes plus a terminator."""
    requests.append((request or b"").decode("utf-8"))
    response = b'{"v":1,"ok":true,"r":{"name":"Ada"}}'
    if capacity > 0 and buffer:
        count = min(len(response), capacity - 1)
        ctypes.memmove(buffer, response, count)
        ctypes.memset(buffer + count, 0, 1)
    return len(response)                      # a negative return would be THIS host refusing

sink = LINE_CB(on_line)                      # keep BOTH callback objects alive: ctypes frees them with the object
bridge = BRIDGE_CB(on_request)

handle = engine.slc_create(b'{"thread":"own"}')

def last_error():
    needed = engine.slc_last_error(handle, None, 0)
    if needed <= 0:
        return ""
    buffer = ctypes.create_string_buffer(needed + 1)
    engine.slc_last_error(handle, buffer, needed + 1)
    return buffer.value.decode("utf-8")

engine.slc_set_output(handle, ctypes.cast(sink, ctypes.c_void_p), None)
if engine.slc_set_bridge(handle, ctypes.cast(bridge, ctypes.c_void_p), None) != 0:
    raise SystemExit(last_error())

# script -> host
engine.slc_run_text(handle,
    b'var who = Bridge.Call(\'{"v":1,"id":"s1","m":"customer.lookup","p":{"id":42}}\');\n'
    b'print("customer: " + who["r"]["name"]);', None)

# host -> script
engine.slc_run_text(handle,
    b'Bridge.Serve(fun (req) {\n'
    b'    if (req.Verb == "echo") { return Bridge.Ok(req.Id, { n: req.Parameters["n"] * 2 }); }\n'
    b'    return Bridge.Fail(req.Id, "NoSuchVerb", "no " + req.Verb);\n'
    b'});', None)

def ask(document):
    data = document.encode("utf-8")
    needed = engine.slc_invoke(handle, data, None, 0)
    if needed < 0:
        return "<status {}> {}".format(needed, last_error())
    buffer = ctypes.create_string_buffer(needed + 1)
    if engine.slc_invoke(handle, data, buffer, needed + 1) < 0:
        return "<status {}> {}".format(needed, last_error())
    return buffer.value.decode("utf-8")

print(ask('{"v":1,"id":"h1","m":"echo","p":{"n":21}}'))
print(ask('{"v":1,"id":"h2","m":"nope"}'))
engine.slc_free(handle)

Details that decide whether it works

  • The buffer parameter is c_void_p. With c_char_p the parameter is an immutable bytes, so the host writes nothing and still answers a length: the engine then parses a document that does not exist. Write with ctypes.memmove and terminate with memset.
  • Keep the callback objects alive. A CFUNCTYPE object owns the native thunk; if Python collects it, the engine calls freed memory. A module-level or function-local that outlives the session is enough.
  • ctypes.WinDLL, not CDLL, and an x64 interpreter.
  • Give the handler a request that HAS an id when the handler echoes it. An absent id is legal (rule 6), and the typed request reads it as req.Id == null, so a handler that echoes it refuses nothing.
  • Read slc_last_error only on a negative status. A contract failure is a document with ok:false.

Java

A Java host reaches the same two exports through the JDK's Foreign Function and Memory API, so there is no JNI, no shim DLL and no second runtime in the process. The declarations are generated too: bindings/ScriptLangCore.java is rendered from docs/embed/abi.json, and it keeps two layers on purpose. Every export is a public MethodHandle under the ABI's own name, so a host that needs a buffer it owns, a NULL Java cannot express, or a call the typed methods do not shape can reach the export directly; the typed methods on top are the convenience, and they apply the same snprintf probe the other bindings do. The sample below is the two directions in one program. The carrier's own check is shipped as bindings/JavaTest.java: it runs the ten checks of Checking a carrier plus every refusal below, ends with JAVA BRIDGE OK, and src/build/java-check.sh compiles and drives it against the published DLL.

// bridge_host.java: both directions over the C ABI, with the generated declarations beside it.
//   javac -d classes ScriptLangCore.java bridge_host.java
//   java --enable-native-access=ALL-UNNAMED -cp classes bridge_host "C:\Program Files\ScriptLangCore\bin"
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.List;

public final class bridge_host
{
    public static void main(String[] args) throws Exception
    {
        Path home = Path.of(args[0]);
        List<String> lines = new ArrayList<>();
        List<String> requests = new ArrayList<>();

        try (ScriptLangCore engine = ScriptLangCore.load(home.resolve("ScriptLangCore.dll")))
        {
            if ((engine.capabilities() & ScriptLangCore.CAP_BRIDGE) == 0)
            {
                System.out.println("this build has no bridge");
                return;
            }

            long session = engine.create("{\"home\":\"" + home.toAbsolutePath().toString().replace("\\", "\\\\") + "\"}");
            engine.setOutput(session, (handle, channel, text) -> lines.add(channel + "|" + text));

            // THE HOST HALF: one request document in, one response document out. answer(...) writes it with the
            // door's own convention and returns the length the engine must be told.
            engine.setBridge(session, (handle, request, answer, capacity) -> {
                requests.add(request);
                return ScriptLangCore.answer(answer, capacity, "{\"v\":1,\"ok\":true,\"r\":{\"name\":\"Ada\"}}");
            });

            // script -> host
            engine.runText(session, """
                    var who = Bridge.Call('{"v":1,"id":"s1","m":"customer.lookup","p":{"id":42}}');
                    print("customer: " + who["r"]["name"]);""", null);

            // host -> script
            engine.runText(session, """
                    Bridge.Serve(fun (req) {
                        var verb = req.Verb;
                        if (verb == "echo") { return req.Ok({ n: req.Parameters["n"] * 2 }); }
                        return req.Fail("NoSuchVerb", "no " + verb);
                    });""", null);

            System.out.println(engine.invoke(session, "{\"v\":1,\"id\":\"h1\",\"m\":\"echo\",\"p\":{\"n\":21}}"));
            System.out.println(engine.invoke(session, "{\"v\":1,\"id\":\"h2\",\"m\":\"nope\"}"));
            System.out.println(lines);
            System.out.println(requests.size() + " request(s) reached the host");
            engine.free(session);
        }
    }
}

Details that decide whether it works

  • --enable-native-access=ALL-UNNAMED is not optional. The Foreign Function and Memory API is a RESTRICTED API, so a JDK 24 or newer refuses every downcall without that flag, and the refusal reads as a broken library rather than as a missing permission. A JDK 22 or newer is required as well, because the API is final from 22.
  • The answer buffer arrives with NO bounds. An upcall hands its pointer over as a bare address, so ScriptLangCore.answer(buffer, capacity, document) reinterprets it with the capacity the engine stated before writing. A copy into the segment as received throws, and the stub turns that into -1, which the engine reads as this host refusing.
  • One arena per handle SLOT. A single arena per handle looks right and is not: installing the bridge released the output stub, so no lines were delivered and then the next line jumped into freed memory. The output slot and the bridge slot are released separately, by the next install, by free or by close.
  • close() releases the callbacks and nothing else. The image's arena is never closed, because the engine's AOT runtime has threads of its own, so unmapping the image would leave them running inside it. slc_free releases a SESSION too, not the library.
  • A host exception does not cross the boundary. The stubs catch it and answer -1, the documented refusal, so a bug in a Java callback is a contract failure in the document rather than an unwind through the engine.
  • engine.setBridge(session, null) takes the host half back, and then Bridge.Call says it has no host by name. A typed method answers "" on a transport failure, so read lastError(handle) when an answer is empty.

COM

A COM client needs no declarations, no buffer and no handle: one ProgID, one member. CreateObject("ScriptLangCore.Session") loads this same ScriptLangCore.dll (the Embed configuration) into the client's own process, and since the server publishes no type library every call arrives as IDispatch: the member's name resolves to a DISPID, then one Invoke runs it, RunText being DISPID 2 and Invoke DISPID 8. The object holds ONE session, created on its first use on a thread the engine starts, and every member is a single job marshalled onto that thread. That is what ties the two verbs together: RunText runs a script in the session's interpreter, so the Bridge.Serve handler it installs is still there when Invoke posts one request document to the same interpreter, where the engine's dispatcher checks the envelope, calls the handler and rebuilds the answer with the caller's id echoed, so what returns is a document rather than whatever the handler happened to write. How one call travels is that path step by step, with the eight members and the three kinds of failure.

# PowerShell as a COM client: nothing to install in this process.
$engine = New-Object -ComObject ScriptLangCore.Session

' The handler answers a CLASS INSTANCE, so the response carries its PUBLIC FIELDS; VBA has no JSON
' parser, so one local reader pulls a top-level field out of the document.
Private Function Field(ByVal document As String, ByVal name As String) As String
    Dim at As Long, piece As String, cut As Long
    at = InStr(1, document, """" & name & """:")
    If at = 0 Then Exit Function
    piece = Mid$(document, at + Len(name) + 3)
    cut = InStr(1, piece, ",")
    If cut = 0 Then cut = InStr(1, piece, "}")
    piece = Left$(piece, cut - 1)
    If Left$(piece, 1) = """" Then piece = Mid$(piece, 2, Len(piece) - 2)
    Field = piece
End Function

That is the whole round trip, and three things in it decide whether the answer is usable. The handler answers a CLASS INSTANCE, so the response's r is a document of its PUBLIC FIELDS (Id, Name, Code) and nothing else: a field is data, while a method or a computed member is behaviour and does not travel. The box belongs to the client, because the server runs in the client's own process, so the dialog appears on the client's screen while the client's thread waits inside Invoke. And Code is Win32's own button id (6 for Yes, 7 for No, 1 for OK), so the script branches on it and the client reads what the script decided rather than re-deriving anything.

How one call travels

Every step below is the same code the C ABI drives, reached through IDispatch instead of an export, so a COM client and a C host cannot disagree about what a document means.

  1. The object is late-bound, and that decides what a client may write. CreateObject resolves the ProgID to the CLSID above, loads ScriptLangCore.dll in-process and asks its DllGetClassObject for a class factory, which answers an IDispatch and nothing else. There is no type library, so VBA declares the variable As Object, GetTypeInfoCount answers 0, and each call resolves its member name with GetIDsOfNames (case-insensitively) and arrives as one Invoke carrying a DISPID.
  2. The object is one session, created on first use, on a thread the engine starts. CreateObject only makes the object; the first member creates the session with {"thread":"own"}, which is an STA thread with 32 MB of stack. That is not a detail: a caller's own thread (Excel's is 1 MB) would trip the engine's depth guard, so the work runs where the interpreter lives. Two objects are two sessions, and each keeps its own handler.
  3. Every member is one marshalled job. The calling thread posts the work to the session's thread and waits for it. A disposed session, a call from a thread that does not own it, and a second call while one is in flight are each refused by name. The host object a script may reach through Com.Host() is registered for that one run and released after it, which is what lets the host application quit.
  4. RunText is a real run of the session's interpreter. Lex, parse, precompile the declarations, interpret: what a snippet declares, and what it serves, stays in that session. The answer is the run's verdict (status, Ok, code, message, line, column, result), or what the snippet printed when it printed anything. A failing snippet is a verdict, never an exception.
  5. Bridge.Serve stores the handler on the running interpreter, together with the file it came from, which becomes the at.file of a failure the engine reports later. Bridge.Serve(null) removes it, Bridge.Served answers whether one is installed, and a session that never served answers NoHandler.
  6. Invoke posts the document to that same interpreter, and the dispatcher decides the contract in a fixed order. Text that is not a JSON object is BadRequest; a v that is not this build's contract version is UnsupportedVersion; a missing or empty m is MissingMethod; a p that is present and is not an object is BadParams; no handler is NoHandler. Then the handler is called with the request as a script dictionary, so req["m"] and req["p"] are the caller's own values, and a handler that throws answers its own error object, with the position and the frames the engine caught.
  7. The answer is rebuilt rather than forwarded. A handler answers the text Bridge.Ok or Bridge.Fail builds; an answer that is not text is HandlerReturnedNothing, and one that is not an envelope with a boolean ok is HandlerReturnedNonEnvelope. The dispatcher then forces v to the contract version, echoes id from the REQUEST (and removes it when the request carried none), and supplies a default e for a failure that forgot its reason. A client therefore correlates on the id it sent, whatever the handler wrote.
  8. It comes back as a BSTR with HRESULT 0, and the document is the whole answer. Invoke does not write LastResult, because the document IS the answer. Free(), or releasing the last reference, ends the session on its own thread, and the handler goes with the interpreter.

Only the first kind travels inside a document. A transport sentence and a snippet's verdict never do, so a client that parses Invoke's answer as JSON can rely on it being a document, and one that wants to know why a run failed reads the verdict RunText answered or LastResult afterwards.

Details that decide whether it works

  • One direction only, and that is the contract rather than an omission. COM carries the host to script direction: the client calls Invoke and the script answers. A script that must CALL BACK needs the host half, which no COM member installs; use the C ABI (slc_set_bridge) for that, or reach the application through Com.Host() when the engine is hosted inside it.
  • The document IS the answer. A contract failure is the answer's own ok:false with HRESULT 0, and a transport failure (a freed object, a session already running) is the sentence in LastError, because a member has no status to answer. Invoke deliberately does NOT write LastResult.
  • A snippet is a SCRIPT, and RunText answers a verdict instead of raising. Every statement ends with its ;, so a Bridge.Serve(...) text missing it answers a ParseError and serves nothing, and the Invoke that follows says NoHandler, which names the wrong thing. On the sample above, removing the ; after }); answers Expect ';' after expression. (expected 'Semicolon', found 'Eof') at line 9 column 3, Bridge.Served is false, and the Invoke that follows answers NoHandler instead of the class instance. Read the verdict while building a handler, and check Bridge.Served in a snippet of its own when in doubt.
  • Register the server first: the installer writes the ProgID ScriptLangCore.Session, the CLSID {4A9D69C4-D9E6-4914-B7DF-ABC442BF5096} and InprocServer32 with ThreadingModel=Apartment. Without installing, setup/com-register.reg does the same for the current user.
  • Late binding and x64 only. There is no type library, so VBA sees Object; a 32-bit Office cannot load the x64 server, and Windows answers "class not registered".
  • A call holds the caller's thread until the script returns, because a session runs on its own STA thread and the COM call waits for it. A handler that shows a modal box therefore holds its client until the box is answered, which is what the VBA sample above does. The engine's own typed route for VBA is the C ABI in assets\language\stdcall\StdCall.bas, which is what a 64-bit Office should use when it needs more than one member.

No re-entry, and threads

The contract refuses re-entry on the same session: a session serves one host request at a time. A handler MAY call the host with Bridge.Call, which is how it asks the host a question while serving.

  • A handler that calls Bridge.Handle on its own session is refused by name: it would be a loop. Bridge.Call is NOT refused by this rule; it is the script-to-host door.
  • A verb issued from inside a host callback is refused, and the refusal comes back as a negative status from that nested slc_invoke. A run posted there would wait on itself.
  • A host that answers Bridge.Call by calling back into the same session is refused the same way. A host that needs to ask a question while answering one posts it to another thread. So the legal call graph is host to Handle, handler to Call, host, with one answer per request.
  • One call at a time per handle. A run is marshalled to the thread that owns the interpreter and the host waits for it, so a second verb arriving meanwhile is refused by name rather than queued. The one exception is slc_cancel, a signal from any thread by design.
  • The host callback runs on the engine's thread, which owns the interpreter. It must not block on the thread that is waiting for the engine, and it must not take a lock that thread holds.

What travels, and what stays home

  • Values travel as JSON: numbers (with their script type), strings, booleans, null, arrays and objects. A script dictionary, a list, a struct and a script class instance cross as the object or array a reader expects, so a host reads a document rather than a type table.
  • A live object travels as a REFERENCE the owning side resolves, for example "acc:17". Lifetime belongs to the owner, and a dangling reference is a code in the error object rather than a freed pointer. That is what makes one contract work for a Python or C host at all.
  • Page inside p, with a reserved key. A contract that allows one huge value invites a payload no reader can bound, so a host asks for a page as { "$page": { "cursor": ..., "size": ... } } (or a list of ids) and the script answers a chunk; the next cursor travels as r.$next, and the last page says r.$done: true instead. The $ keys are the contract's, not the application's, so one generic client can page a verb that opts in without knowing its domain, and a verb that does not read $page simply sees an ordinary member it may ignore.
  • Retrying a request is the application's contract. retry: true invites the host to send the same request again, so the handler owns making that safe: id is the correlation handle and the natural idempotency key, and the dispatcher does not dedupe. A verb that cannot be retried answers retry: false (the default) with a code the host can act on; when the handler knows the delay, it also sets retryAfter.
  • Pipelining is not available on any carrier today. id exists so an answer can be matched to its request in a log; a carrier marshals one call at a time (see No re-entry, and threads), so a host sends its requests in sequence, or a future batch, which version 1 does not define.
  • Add verbs, never re-mean them. A new m needs no version change; removing one, or changing its parameters, does. A reader tolerates members it does not know.
  • Nothing about the host leaks into the script. A COM client, a Python process and a C launcher all answer the same document for the same verb, which is the property the five probes below check identically.

Paging a big result: a sqlite dump, page by page

The paging keys are what make the contract usable as a data pipeline, and they need no engine feature: a verb reads one page, answers it, and says where the next one starts. assets/language/repl/interop/bridge_pipeline_test.slc is that recipe as a pin, driven by a stub host that is the same script.

var db = Sqlite.OpenDb(Application.DataPath + "/reports.sqlite");
var total = 0;
foreach (var r in Sqlite.Query(db, "SELECT COUNT(*) AS n FROM rows")) { total = r["n"]; }

Bridge.Serve(fun (req) {
    var p = req["p"];                                  // the host's cursor and size
    var rows = [].ToList();
    foreach (var r in Sqlite.Query(db, "SELECT id, name, body FROM rows ORDER BY id LIMIT ? OFFSET ?",
                                   [p["limit"], p["offset"]])) {
        rows.Add({ id: r["id"], name: r["name"], body: r["body"] });
    }
    var next = p["offset"] + rows.Count;
    var done = false;
    if (next >= total) { next = null; done = true; }
    return Bridge.Ok(req["id"], { "count": rows.Count, "rows": rows, "$next": next, "$done": done });
});

The host walks it with one request outstanding, because no carrier allows two:

var offset = 0;
var received = 0;
while (true) {
    var answer = Bridge.Call('{"v":1,"id":"page-1","m":"db.page","p":{"offset":' + offset + ',"limit":1000}}');
    if (!answer["ok"]) { print("page refused: " + answer["e"]["code"]); break; }
    received = received + answer["r"]["count"];
    var next = answer["r"]["$next"];
    if (next == null) { break; }
    offset = next;
}
  • The keys are the contract's, the cursor's own shape is not. $page, $next and $done are reserved so one generic client can page a verb that opts in; what travels inside p (an offset and a limit here, a keyset cursor or a list of ids elsewhere) is the application's business, and a verb that does not read $page simply sees an ordinary member it may ignore.
  • Resume, never restart. A page lost in transit is recovered by sending that request again, because the cursor travels in $next instead of living on the server. id is the correlation handle and the natural idempotency key, and the dispatcher does not dedupe, so a handler whose page has an effect owns making a repeat safe, and answers retry: false otherwise.
  • The tail says so. A page past the end answers count: 0 with $done: true and no $next, and a page that runs past the end answers only the rows that are left, so a host stops on the document rather than on a count it was told in advance.
  • The host pulls; nothing pushes. A dump, an export or a report is this shape by construction, while rows that must arrive AS THEY HAPPEN are a different door: http.StreamLines and http.StreamEvents write a chunked body, JSONL or SSE, that a client reads line by line. A script cannot send pages on its own.

Checking a carrier

Every one of the six carriers was driven through the SAME ten checks, so a difference between them is a difference in the carrier and not in what was asked of it:

  1. the capability bit 0x200 says this build has the bridge, and slc_abi_revision is at least 6;
  2. a session is created;
  3. the host callback is installed;
  4. Bridge.Call reaches the host and answers its document;
  5. the host callback received the request document, verb and all;
  6. a script serves a verb, and slc_invoke (or Invoke) doubles 21 and echoes the id;
  7. an unknown verb is a CONTRACT failure inside the document;
  8. a request that is not JSON, or names another version, is a contract answer rather than a transport failure;
  9. the host half can be removed (slc_set_bridge(NULL)), and then Bridge.Call says so by name;
  10. the session frees, and a freed object or handle says so instead of crashing.
