What it is

ScriptLangCore runs .slc scripts, a C#-flavoured language with classes, interfaces, generics, structs, tuples, pattern matching, lambdas, coroutines, async/await, exceptions and a full Windows UI toolkit. A script is a text file; the engine lexes it, parses it into an AST, and runs it on one of two engines: a bytecode virtual machine for the bodies it can compile, and a tree walker for every shape it cannot, so a script never depends on what the compiler accepted.

The runtime is NativeAOT: the .NET runtime is inside the executable, so a machine needs Windows and nothing else, with no .NET installation, no Visual C++ redistributable and no Universal CRT redistributable. The engine itself is written in C# and reaches Windows through flat P/Invoke calls rather than through a framework on top.

Four shapes, one engine

The command line: ScriptLangCore.exe

Runs a file, compiles it to a bundle, dumps bytecode, or opens a REPL. 18.8 MB, self-contained.

The engine as a DLL: ScriptLangCore.dll

A C ABI of sixteen slc_* verbs, plus SQLite extension functions, so a host in C, C#, Python, PowerShell or bash can create a session, run scripts, call into them and read the outcome as JSON. 18.8 MB, 64-bit.

The launcher: ScriptLangCore.Launcher.exe

A 1.2 MB shortcut onto the engine's own entry point, so a script can be packaged into its own Windows executable with the engine beside it. 1.1 MB.

Inside SQLite: the same DLL

.load the DLL into any 64-bit sqlite3 and six functions appear, so SQL can evaluate a script expression over a row, fold a set, or map a list. no extra install.

Why it is built this way

One engine, not two. Bodies the compiler can model run on the bytecode VM; the rest run on the tree walker, and the two are kept at parity by tests that run the same script through both and compare the answers.

No runtime to deploy. NativeAOT means the artifact is the engine. The published DLL and exe import eighteen Windows libraries and nothing else, and the C runtime is linked in.

Checked against the shipped binary. The test corpus (530 scripts) is the instrument, together with the sweeps that compile every script, compare a compiled bundle with the script it came from, and re-run the same script on both engines.
